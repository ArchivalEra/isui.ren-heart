仓库维护细则

本细则适用于任意数量课程的学习仓库：增加课程、增加资料类别、迁移目录都不需要改写本细则，只需要按下面的固定动作执行。原则性规定见仓库维护条例；两者冲突时以条例为准，并同步修订本细则。

与 README 的关系：README 的课程目录和本文件的「仓库状态」都是自动区块，由 .githooks/hook_lib.py 在每次提交时从暂存内容重新生成，推送前校验一致性。手工改动会被覆盖；要改内容，改自动区块之外的正文。

1. 每次编辑后的固定动作（强制）

任何一次新增、修改、移动或删除资料之后，按顺序执行：

bash 
python3 .githooks/update-readme.py --worktree   # 同步 README 课程目录 + 本文件状态区块
python3 .githooks/check-markdown.py             # Markdown 美观度，错误必须为 0
python3 .githooks/test-update-readme.py         # 目录、白名单、命名、索引集成测试
python3 zreflect/facts.py --render-doc STATE.md # 事实系统：重渲染机器块（改了计数才需要重测，
                                                #   见 §1.1；这条只重渲染，缺台账会退 2）
git fsck --no-progress                          # 仓库对象完整性，不应有输出
git diff --check                                # 空白与冲突标记

都通过再提交。提交由 pre-commit 再次生成两处自动区块并跑全部事实系统闸门；推送由 pre-push 校验待推送提交 + 机器块新鲜度。

1.1 事实系统（数字的唯一产地）

计数类数字（课程数、资料数、习题数、配图张数、词条数、站点页数、测试项数）只在 FACTS.json 里生产一次，文档引用写 [[键名]]。改完东西发现计数变了：

bash 
python3 zreflect/facts.py                       # 重测并写台账（掉条/改口会拒绝写盘）
python3 zreflect/facts.py --render-doc STATE.md # 把新数字渲染进 STATE.md 的机器块
python3 zreflect/registry.py --run commit       # 全部提交相位闸门（off 单列，没查 ≠ 通过）

  • 改口要逐条放行：--accept-changes=键名 —— 含义是「这个数真的变了」，不是「让闸门闭嘴」。
  • 被推翻的旧值进 retractions.json（旧片段不许无标记地回到活状态文档）；已知手抄旧值 用 invariants.json 按片段拦（配图张数的 150 就是这类）。
  • 悬案放 questions/，每条要带 **Status:** 与可区分的 **Settling:**。
  • 开工先读 STATE.md（活状态）；会话开始会自动注入未结案悬案与台账规模。
  • 机制文件在 zreflect/，来自 Einfacht 上游、逐字节照抄（可原样升级）；本仓要量的东西在 zreflect/measure_edu.py；配置在 reflect-hooks/Einfacht.env。

2. 新增一门课程

  1. 在 课程/<中文课名>/ 下按类别建目录：默认五类（作业、教材解析、课堂笔记、原始资料、音频）；该课已在 .githooks/hook_lib.py 的 COURSE_SKIPPED_KINDS 声明豁免的类别不建（如形势与政策不建教材解析）。
  2. 每类复制 模板/ 下对应模板生成 index.md；课程入口 课程/<课名>/index.md 复制 模板/课程索引.md。
  3. 在 课程/index.md 登记这门课；在 .gitignore 为每个新文件加一行 !/完整相对路径。
  4. 若该课需要新的豁免类别，先在 COURSE_SKIPPED_KINDS 增加声明再建目录——豁免漏登记会被钩子按「课程入口缺少分类链接」拦下。
  5. 跑第 1 节的固定动作，然后提交。

不需要改本细则、README 正文或钩子脚本——自动区块会自己反映新课程。

3. 教材照片归档与读图

3.1 归档

  • 原件不入库，但必须归档副本（2026-10-28 站长定案，本节此前的「不转格式、不压缩」已作废）： 仓库内不存放图片二进制；原件按课程归档到 /mnt/hdd/study/<课>/原始资料/，一律转成 JXL（JPEG XL）， 文件名去掉原扩展名、加 .jxl。
    • 工具：libvips 一步到位（2026-10-28 定，libvips-tools 已装）： vips copy in.heic out.jxl[distance=0,effort=7] 直接读 HEIC/JPEG/PNG/WebP、直接写 JXL， 不需要中间态（实测 3072×4096 手机照 1 秒/张；magick→PNG→cjxl 两步要 5 秒且纯属浪费）。
    • 无损是硬要求：distance=0。有损版小得多（同图 339KB vs 1.7MB），但归档不省这个空间。
    • 验证可逆，统一判据 compare -metric AE：vips copy 原图与归档件各解成 PNG， compare -metric AE 原 归档 null: 输出 0 才算过。JPEG 的「逐字节相同」只在不经 libvips、 直接用 cjxl 无损转码时成立；走过 libvips 一律按像素判。
    • 原 SHA-256 仍然有效：正文与 原始资料/index.md 登记的是归档前原件的哈希。 ⚠️ 顺序不能反：先算原件哈希 → 再转码 → 验证可逆 → 最后才清原件。 HEIC→JXL 是无损转像素、不保留原容器字节，原件一删、那份哈希就永久算不回来 （2026-10-28 首批 13 张 HEIC 踩过，只能改登记归档件的哈希并注明口径）。
    • 批量归档用 python3 工具/归档-jxl.py <课名> <文件...>（libvips 一步转码 + 逐像素验证 + 打印两边哈希）。
    • 分类按课程、不按来源（/mnt/hdd/study/README.md 同规）；文件名原样保留，只换扩展名。
  • 在 课程/<课名>/原始资料/index.md 逐张登记文件名、原书页码/内容与 SHA-256，并在表格里把文件名写成纯文本（不加链接，避免死链）。这是原件的身份凭证。
  • 登记后逐张核对：登记哈希 = 拍摄者本地原件哈希。核对命令见维护条例第 6 节验证基线。
  • 需要方向校正、缩放或裁剪来读图时，由 .githooks/prepare-photos.py 从仓库外原件生成 /tmp 阅读副本；副本不入库、不作证据引用。
  • 解析正文引用照片时用文件名（如 IMG20260917203306.jpg）或页码，不写仓库内路径。

3.2 读图（强制交给子代理）

主对话每对话最多 60 张图片，超限后主代理无法再读图，会把整批任务卡住。因此：

  • 批量读图一律派子代理：用 Agent 工具（general-purpose）分批读，一个子代理读 4–8 张。提示词只列出要读的具体那几行字（某个下标、某个标注），并写明「不要转录整页正文」。
  • 每张图只读一次，看不清就上报重拍：禁止重复打开同一张、禁止换副本重试、禁止裁剪/放大/增强等自救手段。读不清的按「文件名 + 原书页码 + 看不清的位置 + 原因」报给用户重拍，由用户决定。正常单张约 1 万 token；若某次读图远超此量级，说明提示词里让它抄整页了。
  • 子代理有独立的图片预算，不受主对话上限影响；主代理只汇总它返回的文字结论。
  • 主代理只在需要目视确认一两个关键点（例如某一步变换标注、某个下标）时才直接读图，并计入自己的预算。
  • 禁止用 OCR 代替读图：公式、矩阵、上下标、手写旁注在识别结果里普遍出错（实测会漏掉 1、负号和下标）。OCR 只能用来辅助定位页码，不能作为转录依据。
  • 子代理只许用 Read 看图，不许自建识别管线：实测有子代理收到「读照片」指令后，自行建虚拟环境、装识别工具、把图旋转缩放截图做探针，整轮作废且结果一字不可用。派活提示词必须写死三条：
    • 只允许 Read；禁止使用或安装任何 OCR／文字识别工具与模型，禁止 pip/uv/apt 安装；
    • 禁止对图片做旋转、裁剪、缩放、增强、拼接；Read 打不开或看不清就立即停下如实报告，不许另找替代方案；
    • 报告开头必须先列「实际打开的文件清单＋未能打开的文件」，没有这份声明的结果一律丢弃重派。
  • 主代理派活时写清：这是第几章第几节、期望的页码区间、需要逐字核对的记号（箭头上的变换标注、下标、符号），并要求区分「数值确定」与「标注看不清」。

3.3 教材解析写作（先抄后析）

  • 一节一个文件，放在 课程/<课名>/教材解析/第NN章-章名/ 下，命名 第NN章-<节号>-<节名>.md；不把整章塞进一个 md。
  • 每个文件内部固定：先原书抄录（按原书页码抄录印刷正文与原编号，公式用 LaTeX 重排），紧跟解析（概念、条件、推导、例题解法、易错点、验算）。
  • 教材陈述与整理者补充必须分开标注；学生手写答案不得当作标准答案；教材习题不自动认定为教师布置的作业。
  • 例题与习题的数值结果要用精确算术独立验算（有理数或整数运算），不照抄书上手写过程；验算发现的差异要写进解析并在文件末尾说明。 能上机器就别手算（2026-10-12 升级）：矩阵、方程组、进制转换一律用 Octave 复核（分数用 [N,D]=rat 取精确值）； 大整数（超 2532^{53}253）回 Python BigInt；符号恒等式取多组数值抽查。分工表与边界见 double-sign skill。
  • 每个文件末尾写「本节完成边界」：只列已抄录、已解析的范围，不写未做表述（缺什么、待复核都归 GitHub issue，见 §3.5）。

3.5 未竟条目归 issue（2026-10-12 定案）

资料页零未竟表述——〔待核对〕、### 待办、待补、整理中、（留空）、未完成 这类字样 在课程资料里一律不出现；缺什么、等什么、哪处要复看原图，全部归档为 GitHub issue：

  • 一条 issue = 一个能独立结案的动作（缺材料 / 待复核 / 待补双签各一族，按课程分）。
  • open = 没补，closed = 补了；提交信息写 Closes #N 即可随推送收口。
  • 建目时先查是否已有同类 issue，别重复开；结案前把结论落回正文（补上的内容进页面，撤下的说明进复盘）。
  • 事实不算未竟：待提供（教材版本、音频链接这类外部材料未到）、尚未提供、未提供 是如实登记的事实，照写；被禁的是「我们欠着这活没干」的表述。
  • ## 本篇没讲的（这节课没讲的课程范围）同样保留——那是内容事实，不是仓库欠账。

3.6 题面必须完整，图必须画在题面里（2026-10-13 定案，全仓适用）

作业页与教材解析页的题面必须自足：只读题面（不展开任何折叠面板、不点开提示） 就能把题完整做出来。具体两条：

  • 题目引用的图（原书图号、截图里的电路/波形）→ 图要跟着题面出现 （习题册的做法：<img> 紧跟题面；作业页配图用内联 SVG）。
  • 题目要求产出的图（逻辑电路图、卡诺图圈组、波形图、状态表……）→ 真画出来， 不能只在解答层写一句「画法说明」。画在题面之后、解答之前的位置， 让同学先看到「要画成什么样」再自己做。
  • 表达自由：题面鼓励用 markdown（表格）或内联 SVG 表达元素；本仓「图像线已放弃」 只指教材原图复刻，不指「题目要求的图」——后者是题面的一部分，必须做。
  • 解答层不必重抄题面（避免重复）。

反面教材（2026-10-13 修复）：电子技术 7.9 三小问要求「画出逻辑电路图」， 初版只在解答里写「用与门/或门/非门画出来」而没画图 —— 已补 3 张内联 SVG 逻辑图； 7.10 要求「用卡诺图化简」，已补 4 张带圈组描边的卡诺图 SVG。

3.7 三签：读了依赖，做不做得出来（2026-10-14 定案）

作业/解析入库依次过三道内容闸，顺序不能反：

  1. 反人类解析（「试探/凑/巧妙看出」= 没写完）→ 2. 双签（独立子代理只拿题面重算，验答案对不对） → 3. 三签（另一个独立子代理只拿题面 + 依赖表指向的内容试做，验「读了依赖做不做得出来、过程合不合理」）。

分工：双签管答案，三签管依赖与过程。双签没通过就不跑三签——答案错了，讨论依赖没意义。

三签的输入（信息隔离）：题面 + 依赖表每个锚点指向的内容（整段抓给子代理）。 不给作业页的「提示/完整解答/复盘」——给了就退化成「看了解答当然会做」。

两步：① 盲做（只凭题面 + 依赖试做，报卡点）→ ② 评解答（此时才给解答，逐条核对）。 四条判据：依赖自足 / 定理闭合（解答里每条定理在依赖里查得到——最易漏）/ 锚点有效 / 过程无跳步。

权力与红线：三签有权直接改依赖表、依赖锚点、作业页的步骤表述（补跳步、补依据、把巧解改写成机械做法）； 不许碰答案数值/结论（那是双签的地盘，怀疑答案要退回双签重算），不许改题面。改完重跑钩子+构建， 涉及答案相关文字则重跑双签，再写三签行。

落笔：完成边界写 三签：<日期>，独立子代理只读依赖试做，可独立完成；解答过程合理（定理闭合、无跳步）； 有缺口则改完再写（写明改了什么）。详见 .agents/skills/triple-sign/SKILL.md。

3.4 资料与索引同进同出（hook 强制）

课程/<课程>/<类别>/ 下任何资料（不含 index.md）新增、删除或修改，同一次提交必须同时改对应类别的 index.md，否则 pre-commit 直接拒绝。索引是资料的登记处；资料变了索引不动，索引就已过期；last_updated 由 pre-commit 按各文件自己的提交日期自动写入，不手抄。作业记录照此办理：新增作业要登记进 作业/index.md，改正文要同步索引里的状态与时间。

5. 白名单与提交

  • .gitignore 保持 * → !*/ → 逐文件 !/完整相对路径，禁止通配符；新增文件先加白名单。
  • 提交信息用中文，说明做了什么；不提交音频二进制、不写入任何凭据。
  • 每次提交后确认工作区干净；推送前确认 pre-push 通过。

6. 禁止事项

  1. 猜补看不清的题面、数值、下标。
  2. 在资料页写未做表述（待核对/待办/待补/整理中）——这些归 issue（§3.5）。
  3. 把 OCR 结果、转换后的临时图、学生手写答案当作权威依据。
  4. 用子代理的转录直接成文而不做数值验算；转录只解决「书上写了什么」，不解决「写得对不对」。
  5. 只在一个位置维护正文，其他位置用链接；不复制第二份。
  6. 凭文件名或日期推断课次、节次；课次以正式资料为准。

7. 故障处理

  • git fsck 报对象损坏：先确认工作区文件与源文件哈希一致，再删除损坏的松散对象（.git/objects/xx/…）并重新 git add 该文件，最后重跑 git fsck。不要用 git gc 掩盖问题。
  • 提交被 pre-commit 拦下：按提示修好命名、索引链接或自动区块，不要用 --no-verify 绕过；该选项只应作为临时诊断手段，且推送端仍会校验。
  • 主对话读图超限：改为派子代理读，或把剩余张数留到下一轮对话继续。
