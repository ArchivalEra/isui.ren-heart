仓库维护条例

本条列对仓库任何时期的任何改动都适用；与 README 冲突时以本条例为准并同步修订 README。

1. 仓库定位与读者

  • 本仓库是给人看的学期学习仓库，不是纯机器格式库。OKF（v0.2）元数据只作轻量结构约束，不牺牲可读性；标题、正文、索引一律中文优先。
  • 仓库代表当前学期，以中文课程名为主分类；每门课默认建五类子目录：作业、教材解析、课堂笔记、原始资料、音频。课程数量可任意增加，规则不随之改写。确无某一类内容的课程可声明豁免（如形势与政策没有可整理的教材正文，不设教材解析）：豁免登记在 .githooks/hook_lib.py 的 COURSE_SKIPPED_KINDS，豁免后该课不建该类目录、课程入口也不必链接它；一旦该课又出现该类资料，仍须照常建目录与索引。
  • 操作规程见维护细则（含随每次提交自动重算的仓库状态区块）；给 AI 助手用的执行流程见 .agents/skills/repo-maintenance/SKILL.md，常驻路由与硬约束见 AGENTS.md（skill 正文不会自动加载，须按该表主动调用）。

2. 真实性与溯源（最高优先级）

  1. 不猜补：教材题面、数值、下标、口误、缺失板书一律不猜。页面上也不留「待核对/待补/待办」类未做表述—— 未竟条目一律归档为 GitHub issue（open = 没补，closed = 补了，见细则 §3.5）； 确需外部材料才能补的事实（教材版本、音频链接）仍按「待提供」如实登记。
  2. 区分身份：教材原文陈述、整理者补充、学生手写旁注三者在解析中明确区分；学生草稿不得当作正确答案直接采信，需独立验算。
  3. 来源登记：每份教材解析注明原书页码与照片来源；教材照片原件不入库，由拍摄者本地保存，仓库只登记文件名、页码与 SHA-256 作为身份凭证；文本类原始文件（如课堂转写）保持字节不变入库并登记 SHA-256。
  4. 不重复维护：同一内容只在一处保存正文，其余位置用链接；课堂例题的规范化重做放课堂笔记，教材解析只登记题面并互链。
  5. 正式作业只认正式来源：教材习题、课堂例题不自动认定为教师布置作业；题号、截止时间以学习通等正式通知为准。

3. 结构与命名

  • 课程目录：课程/<中文课名>/<类别>/；各类入口为 index.md。
  • 日期类资料（作业、课堂笔记、音频记录）：YYYY-MM-DD-名称.md。
  • 教材解析：一节一个文件，放在章目录 教材解析/第NN章-章名/ 下，文件名为 第NN章-<节号>-<节名>.md；一节内容过多时在该文件内按二级小节继续拆。不把整章塞进一个 md。
  • 每个教材解析文件内部固定先写原书抄录（按原书页码抄录印刷正文与原编号），紧跟解析（概念、条件、推导、例题解法、易错点、验算）。抄录与解析同文件、分小节呈现，先抄后析，便于逐句对照。
  • 新建课程：复制 模板/ 下对应模板建立各类 index.md（默认五类，确有豁免则建剩余各类），并同步登记课程总索引与课程入口。
  • knowledge/（历史兼容入口）已于 2026-10-17 删除；旧链接直接看 课程/ 对应目录。

4. Git 流程

  1. 精确白名单：.gitignore 保持 * → !*/ → 逐文件 !/完整相对路径，禁止通配符；每个新文件先加白名单再 git add。
  2. hook 必须启用：克隆后执行 git config core.hooksPath .githooks；提交由 pre-commit 生成 README 与维护细则两处自动区块，推送由 pre-push 校验待推送提交树。
  3. 每次编辑教材解析（或任何资料）后：运行 python3 .githooks/update-readme.py --worktree 同步 README 课程目录与维护细则状态区块，再 git status 确认无意外改动。
  4. 提交前自检：python3 .githooks/test-update-readme.py 全绿；python3 .githooks/check-markdown.py 无错误；git diff --check 干净；真实暂存区保持为空直到正式提交。
  5. 迁移、移动文件必须保持链接有效（hook 会拒绝断链），删除资料时同步更新分类索引。
  6. 资料与索引同进同出：课程/<课程>/<类别>/ 下任何资料（不含 index.md）有变动——新增、删除、修改都算——必须在同一次提交更新对应类别的 index.md，否则 pre-commit 拒绝提交。索引是资料的登记处，资料动了索引不动即为过期；last_updated 由 pre-commit 按各文件自己的提交日期自动写入，不手抄。
  7. 图片阅读交给子代理：主对话每对话最多 60 张图片，批量读图必须派子代理完成；禁止用 OCR 结果代替读图。子代理只许用 Read 工具看图，禁止自建 OCR／文字识别管线（含安装识别工具、对图片做旋转裁剪缩放等加工）；看不清就停下如实报告，不得另寻替代方案，报告须先列实际打开的文件清单。

5. 音频与外部材料

  • 音频目录只存下载链接与元数据（课程、日期、准确课次/节次、主题、链接来源与有效期、关联笔记），不提交音频二进制，不写入任何凭据。
  • 课次编号、节次必须由正式资料确认，不得凭文件名或日期推断。

6. 验证基线

任何改动后应保持（当前基线，2026-09-18）：16 项集成测试通过；本地链接全部有效；git diff --check 通过；README 与维护细则两处自动区块与工作区一致；Markdown 美观度检查无错误。

  • python3 .githooks/test-update-readme.py：目录、维护细则状态、白名单、命名与索引的集成测试。
  • python3 .githooks/check-markdown.py：Markdown 美观度与可读性检查；错误项必须为 0，--strict 时警告也失败。检查标题层级、表格列数、代码围栏与数学定界符闭合、行尾空格、空行、超长行，以及数学模式内未用 \text{} 包裹的中文（该写法会让 KaTeX 解析失败）。
  • git fsck --no-progress：仓库对象完整性，不应有输出。
  • 教材照片：以 原始资料/index.md 登记的 SHA-256 与拍摄者本地原件逐张核对；原件不入库，仓库不存图片二进制。
  • 迁移完整性检查脚本由当次会话在 /tmp 运行，不入库。
